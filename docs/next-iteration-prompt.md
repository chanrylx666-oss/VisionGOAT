## 3. 对齐的业务逻辑

### 3.1 图像、定位和测量结果分别绑定

每个支持定位的工具至少能明确选择：图像来源、定位来源、目标选择方式、ROI、算法参数和判定规则。默认可继承直接上游，存在多个候选时必须能看见并修改绑定，不能随意取第一个匹配结果或最近一个节点。

例如圆查找可以使用“灰度转换后的整图”作为图像来源，同时使用“模板定位的目标 0”作为位置来源；它不应被迫只处理模板裁图。主连线可作快捷绑定，详细来源在参数面板展示，无需用户额外插入 ROI、取字段、计数或显示模块。

### 3.2 单端口承载完整结果，连线保持类型安全

- 保留并扩展现有结果包，至少可表达 features、selected、measurement、count、found、decision、overlay、图像引用、坐标上下文、诊断；名称可沿用已有类型，禁止无迁移改名。
- 图像引用必须对应真实像素及有效掩膜、生命周期；图像元数据 JSON 不能冒充图像帧。不会产生图像的算子不得捏造 Image 投影。
- 下游需要具体类型时，绑定到稳定字段路径，例如“圆查找 A／选中圆／圆心”。有多个 Bool、图像或数值候选时给出选择及说明，不自动猜测。
- 一个输出可以扇出到多个节点，各分支不得原地修改共享像素、ROI 或结果。
- 一个目标选中索引越界，即使上游 count 大于 0、found 为 true，选中结果仍然不可用。下游不得继续用旧目标，也不得悄悄改用目标 0。
- 公开结果及必要关联图像不依赖打开 Debug。完整中间图按需保留、受内存预算约束，不能为了方便给每个节点永久复制整幅大图。

### 3.3 多输入、参数绑定和调度必须一起实现

- 为原生组件建立输入端口集合，定义必填／可选、类型、缺省值及语义。给旧零／单输入算子提供兼容适配，不为迁移重写所有已验证算法。
- 配方能保存多个输入绑定，包括 Image、Pose/Transform、Point、Line、Circle、标量等实际需要的类型。结果字段绑定必须经过解析、类型校验和运行时取值，不是任意 JSON 隐式转换。
- 参数值支持“常量、公开输入、上游结果字段”时，要显式记录来源；同一参数只有一个生效来源，禁止含糊的覆盖顺序。
- 图像连线、几何输入和参数绑定都形成依赖关系：参与环路检测、执行顺序、祖先子图计算、引用计数释放、缓存失效和节点删除／复制／撤销。不能只检查画布上可见的线。
- 使用稳定节点／端口／字段 ID，改显示名不能破坏连接。未知字段、负索引／错误类型等静态非法配置、未连接必填输入在运行前给出中文节点级诊断。合法的非负索引超出本帧检测数量时，属于运行时无有效选择，按空选中结果传播，不把正常空检测变成配方错误。
- 本轮允许同一输入帧派生的不同分支参与测量；暂不扩展为多相机同步。不同帧、不同原始图像或无共同坐标映射的数据默认拒绝组合。
- 教学图、模型和参考位姿是已冻结并校验版本的配方资源，不要求与检测帧同帧；“同帧”约束针对本次运行的图像、运行定位结果和被组合测量值。

### 3.4 统一坐标、单位和定位基准

- 区分原始图像坐标、裁图局部坐标、工件坐标和将来的标定坐标。结果记录坐标空间及单位；默认公开二维几何为原图像素坐标，X 向右、Y 向下。
- 图像携带来源身份和到原图的映射；originX/Y 只能描述平移，不能冒充旋转、缩放或仿射矩阵。
- 定义唯一角度单位、零方向、正方向、范围及变换乘法顺序，所有 UI、算法、SDK 和叠加显示一致；沿用现有图像坐标的角度约定并提供测试。
- 保存参考模板位姿与运行位姿。参考图中绘制的点 p 应按 T_run × inverse(T_reference) × p 映射到当前原图；若采用工件局部坐标存储，明确等价变换并验证逆变换。
- 每一帧从未变换的教学基准计算当前 ROI，禁止在上一帧已经变换的 ROI 上继续累乘；反复移动、旋转和恢复原位不得积累漂移。
- 模板默认定位点是教学模板框中心，允许后续提供可编辑基准点；中心点、匹配框左上角、旋转枢轴和测量点不可混用。改变基准点或重新学习模板时明确更新或失效关联 ROI，不能让旧 ROI 静默偏移。
- 本轮 Fixture 支持平移、旋转和等比缩放。任意仿射／非等比缩放不在本轮承诺中；圆在非等比变换后应是椭圆，禁止仍输出一个虚假圆半径。
- 默认在原始像素上变换 ROI 和采样位置；只有明确的图像几何变换工具才重采样整图，并记录插值、有效区及逆映射。尺寸测量不能因图像显示缩放而变化。
- 不为全图恢复而绕过上游灰度处理、裁图或有效掩膜；不把匹配模块自己的搜索范围当作下游测量的硬边界。
- 没有真实标定时，结果单位是 px / px² / deg，不允许贴上 mm 标签。

### 3.5 结果可用性、执行状态和产品判定分离

- 成功执行但未找到目标，属于成功的空检测；返回空集合、空选中对象、明确原因。没有有效输入的依赖节点按契约跳过或返回不可用，不回退全图，不复用上一帧。
- 区分“算法成功”“有无检测到目标”“测量值有效”“尺寸符合公差”。数值 0 是合法数值，不能用它代表缺失；NaN/Infinity 不能冒充可用结果。
- 业务判定至少有 Pass、Fail、Unknown；未配置规则、输入不可用、失败或取消不能默认 Pass。“期望目标数量为 0”是显式规则，可以对成功的空检测判为 Pass。
- 现有 inspection 配方的 decisionOutput 是 Bool，成功时只能得到 Pass/Fail。新增三态判定或“值＋有效性”契约，并同步原生总判定、配方决策投影、SDK 和 UI；不能只给结果 JSON 加一个 decision 字段。保留旧 Bool 判定路径的原语义，Unknown 不得偷偷转换为 false，也不得为表达 Unknown 伪造执行失败。缺孔默认使尺寸判定 Unknown；明确配置“必须找到目标”时，有无检测规则可判 Fail，整体聚合策略须可解释。
- 任一依赖或参数修改、换图、模板更新都使旧结果失效。允许展示上一帧快照时必须标记其帧号和过期状态，禁止作为本次依赖使用。
- 同一会话只运行一个任务，忙时返回 Busy。接受任务时冻结输入帧、常量、公开输入、配方／模型版本和字段绑定定义；上游字段值只能从本次 Run 的对应节点执行结果解析，不能从 UI 中的旧结果取值。UI 后续编辑不会改变已开始执行的任务。
- 整体执行失败沿用现有“公开结果清空、业务判定 Unknown”。节点诊断可保留，但不得被正常结果 Getter 当作成功结果读取。
- 取消／超时必须等待原生计算安全收尾；对自行实现的搜索循环可增加协作检查，不通过提前释放帧伪造即时取消。

卡尺至少完整覆盖：数量、投影宽度、搜索长度、平滑、边缘极性、搜索方向、对比度阈值、边缘选择规则、剔除点数或比例、最少有效点及拟合残差。剔除数量和比例若都提供，要定义互斥或优先级；不允许剔除后少于有效拟合点数仍报成功。

投影宽度需要奇数时，在 UI、配方验证和原生执行保持同一约束及中文说明。缩放后的采样间隔、长度和数量要有明确物理意义：本轮 ROI 几何及卡尺宽长随等比缩放，卡尺数量不随缩放；实现内部整数窗口归一化时记录实际值，预览和运行一致。边缘阈值等灰度量不乘几何尺度。

直线的无限延长线与有限线段距离不能混淆。夹角的取值范围、交点在平行或近乎平行时的无效条件、圆心距与圆边缘最短间距的区别，都在参数帮助、类型和测试中体现。本轮先实现表中明确的几何量，不用公式拼接假装已支持所有几何测量。

常用公差判断内置在测量工具，不强迫额外连接一个比较节点；也可提供有独立用途的“综合判定”供后续复用。原有数量判断继续可用，found 与 passed 不得混用。

已有结果包的 passed 表示数量规则合格，必须保留该字段原有含义及类型。尺寸公差与综合判定使用明确的新契约，不静默把 passed 改成“所有尺寸合格”。同时配置数量与尺寸规则时，分别输出规则结果，并记录配方总判定采用哪些规则和聚合方式。

**材料内外径、壁厚、同心度不在本轮默认完成项中。** 后续新增时必须分别检测真实内外轮廓并定义厚度／同心度算法，不能将当前配置的输出环带宽冒充壁厚。

## 5. 后续算子与平台路线图：M3～M6

这些内容记录目标和接口方向，首批不创建假入口或声称已完成。执行到相应里程碑时，先核对已有实现再细化测试。

| 里程碑 | 业务能力 | 主要算子及交付要求 |
|---|---|---|
| M3：分割、Blob、质量检查 | 常见有无、数量、面积、外观检测 | 灰度／通道选择、反色、归一化、滤波、固定/Otsu/自适应阈值、形态学；集成 Blob：分割→清理→连通域→特征筛选→排序→数量/尺寸判定；灰度／颜色统计；同尺寸图像差分与运算 |
| M4：多目标与复用流程 | 一个模板找到多个工件，每个工件执行相同检测 | 有限 ForEach、子流程、类型化公开输入输出、分支条件、结果聚合；多模型模板选择、目标排序、选择策略；材料内外径／壁厚、同心度、椭圆、矩形、角点等扩展 |
| M5：采集与标定 | 工业相机取流，测量结果进入工程坐标 | 海康 MVS／大恒 Galaxy GigE 适配、预览和触发检测；像素比例、N 点平面坐标标定、畸变校正及适用性说明；独立标定资源及版本 |
| M6：识别、缺陷与生产集成 | 产品识别、记录、追溯、与设备交互 | 一维／二维码、OCR／OCV；定位后的标准件差分与缺陷区域筛选；结果/图像保存与批量回放；协议适配、PLC/IO/光源接口；按需求再加入统计报表 |

扩展细则：

1. **Blob**：区分像素面积与轮廓多边形面积、外轮廓与孔洞；明确 4/8 邻接、边界目标和孔洞策略。输出面积、质心、外接框、方向、长宽、周长、圆形度、孔洞数量等实际计算的特征。现有轮廓面积不能换个名称冒充白像素数量。优先一个集成 Blob 工具，保留必要低层工具用于复杂流程。
2. **多目标**：resultIndex 只是本帧选择，不是目标跟踪 ID。定义按得分／位置的稳定排序、数量上限、单目标失败策略和空集合策略。ForEach 的局部参数、ROI、结果和缓存隔离，每项携带父目标索引；目标未检出、测量失败不能因过滤掉失败项而变成全体合格。循环受总时限与内存预算约束，外部图仍无隐式环。
3. **子流程与条件**：类型化输入输出与稳定标识；禁止递归及未界定的循环。定义跳过分支的输出为空和下游行为，不能用上一轮值补齐。脚本引擎不作为首批依赖，普通配置就能完成常用检测。
4. **采集**：沿用“GigE、持续预览、触发时检测”。业务检测触发与相机曝光触发分开；默认业务请求使用接受之后的新帧，标明帧号、相机序列号、时间和请求 ID。预览只保留最新帧；检测帧具有独立所有权；忙、超时、断线、停止和重连的收尾明确。
5. **相机环境**：厂商适配可选、动态加载；缺 SDK 不影响文件图运行。以实际安装 SDK 及设备能力实现，不用普通 VideoCapture 冒充厂商 GigE 采集。没有设备时完成模拟器和契约测试，实机性能、断线、曝光和丢帧验收明确标为待测；不宣称已接通大恒或保证任意分辨率 30 FPS。
6. **标定**：输出标定模型、单位、参考坐标系、误差、适用平面／范围及资源摘要。像素、工件位置修正和真实世界坐标变换分别管理。透视或非等比变换后圆不一定还是圆；真实尺寸应对采样点或正确几何映射求得，不能把一个像素长度随意乘常量作为所有位置的 mm。
7. **读码／OCR**：选用有维护、许可证明确、可部署的真实引擎并验证目标码制／字符集。输出文本、位置、置信／质量及有效性。OCR 是识别、OCV 是按期望内容验证，不能混为一谈；没有模型或依赖时不生成假文本结果。
8. **缺陷检测**：先定位对齐，再考虑光照归一化及差分；阈值、面积、尺寸和掩膜筛选可调，输出真实缺陷区域。先做传统二维检测；深度学习、3D、GPU、机器人运动控制不作为默认扩展。
9. **通讯与追溯**：WPF 宿主负责设备交互是默认集成路径；平台内协议插件按明确设备需求再实现。若实现 PLC 请求／完成／确认流程，使用请求 ID、Busy、超时和重试去重，避免重发造成重复动作。图像与结果保留原始帧／配方版本／参数快照及有限磁盘保留策略。

## 6. UI、配方和 SDK 必须同步完成

- 工具箱分类：输入、预处理、定位、测量、分割/Blob、识别、判断、流程、输出。已有功能优先集成，隐藏内部辅助算子仍可读取旧配方。
- 参数全部在程序内修改；与原生目录共用类型、范围、步进、单位、枚举和约束。条件参数按算法模式显示，参数非法时定位字段并说明修复方法，禁止只弹原始英文／JSON。
- 节点双击进入参数；图中直观看到运行状态及耗时。选中节点即显示本次输入、输出、原图坐标、有效性和测量表，不需要追加显示模块。
- 图像视图提供原图／处理图／中间结果切换、缩放和平移、ROI 编辑、定位轴、卡尺窗、有效／剔除边缘点、结果轮廓的独立开关。屏幕缩放不改变测量坐标。
- 本轮提供单次运行和运行到选中节点；后者必须执行当前绑定的完整祖先依赖，不能拿过期缓存拼结果。验收数据批处理由测试工具完成，面向用户的产品批量回放留到 M6。
- 模板／ROI／定位基准编辑支持撤销重做、保存重载。多选、复制节点时重映射内部 ID 和绑定；删除有依赖节点需提示或使依赖明确失效，不保留幽灵引用。
- 配方内保存模板、基准、ROI、绑定、判定和所需资源，使用现有摘要及路径验证；引用外部教学图片的绝对路径不能成为运行必需条件。相机连接配置与算法配方分开。
- 保存失败保留旧文件；缺资源、未知版本、依赖不兼容要准确报告。新格式使用必要的版本／最低运行库声明和可验证迁移，不能只修改 schema 数字。
- C++ 核心与 C# 之间仅交换受控 ABI 数据及句柄，不跨边界传 cv::Mat、STL、WPF 对象。新增类型有明确释放、并发及不可用值语义。
- SDK 对新算子提供强类型结果、统一状态与坐标单位；保留原有 Getter。只有 ABI 确实不兼容才升级主版本，新增导出也要检测运行库能力并给出版本不匹配提示。
- SDK 调用和编辑器执行使用同一个原生计划。配方公开输出名由用户决定，不能硬编码某个示例节点名字。
- net8 兼容要由真正的 net8 Windows 宿主运行证明；只编译 net8 库，再在 .NET 10 进程中运行不能算 net8 运行验收。环境缺少相应运行时时注明缺项，保留已完成的构建及其他验证，不虚报兼容结果。
- WPF 的叠加图元支持本轮新增形状，包括旋转矩形、圆弧／扇环；不能把所有圆弧都画成整圆。渲染变换与数值结果一致，在正确 Dispatcher 更新，Dispose 后的托管结果和拷贝图像仍按既有契约可用。
- 组件扩展保持一个可信元数据来源。新增普通 OpenCV 算子不要求同时在多个 UI switch 中硬编码名称、参数和端口；复杂教学界面通过清晰的专用扩展点接入。

## 7. 验收标准：以真实运行结果为准

M0～M2 至少完成下列验收并保存配方、输入、预期、实际结果及报告。工具类数学测试不能代替真实 Runtime 和 WPF 流程测试。

| 场景 | 验收要求 |
|---|---|
| 原有功能 | 原有有效配方、单口显示、模板教学、ROI、卡尺、大图和公开 SDK 路径仍通过受影响回归；旧默认行为不变 |
| 两圆中心距 | 从模板定位的不同工件位置正确测量两个真实圆；两来源绑定实际参与原生运算，关闭 Debug 后公开结果仍可读取 |
| 位姿变化 | 至少覆盖参考姿态不为零、平移、正负旋转、跨角度边界、0.8/1.0/1.2 等比缩放；ROI/卡尺预览与采样位置一致 |
| 数值真实性 | 测量中心来自边缘，模板中心故意与圆心不同；图上中心距随等比缩放变化，禁止为了“对齐”强制保持相同像素距离 |
| 坐标恢复 | 前序灰度、裁图、非零 origin、多层 ROI 与有效掩膜同时存在时，公开结果和叠加图形正确回到原图 |
| 空结果／旧结果 | 第一帧成功，第二帧无匹配／缺孔／选择越界／ROI 全越界；不显示或使用上一帧成功值，不错误判 Pass |
| 多输入 | 两个不同上游、同源不同分支、选中对象为空、类型不符、字段不存在、绑定形成环、跨帧不一致，均按契约执行或拒绝 |
| 几何退化 | 平行线交点、零长度线、有效边缘不足、剔除过多、重复点及 NaN/Infinity 等有明确不可用状态，无崩溃和假零值 |
| 卡尺／双边 | 亮暗极性、反向搜索、边缘不成对、噪声／遮挡、边界和宽度公差可复现；拟合点与剔除点可查看 |
| 判定 | 下限、上限、略低／略高、未配置、无效输入、期望数量为零分别验证；显示舍入不改变判定 |
| 保存与兼容 | 编辑、撤销、复制、保存重载后几何／输入绑定／公开输出／摘要一致；旧格式使用旧语义，新格式能检测旧运行库不支持 |
| 宿主一致性 | 同一配方、参数及帧在编辑器和 net8 SDK/WPF 宿主得到相同数值、状态、目标选择和图形；不要求启动编辑器 |
| 资源与运行 | Busy、取消、超时、Dispose、连续运行内存、分支共享像素和结果生命周期检查；不提前完成取消后继续使用已释放缓冲 |
| 大图 | 沿用既有输入上限，至少真实导入 5120×5120 测试图做定位→局部测量；工作图缩放和精度影响有记录，不靠缩小用户原图绕开问题 |

精度测试分开报告：坐标变换的数学误差、定位误差、边缘拟合误差、真实工件重复性。合成清晰圆初始验收目标可设中心误差不超过 1 px、直径误差不超过 2 px、两圆中心距误差不超过 2 px，并注明分辨率、角度、尺度、算法及测试集合；若无法达到，分析原因并报告，不通过删除失败样本或扩大容差掩盖问题。这不是产线精度或亚像素精度承诺，实物验收另需真实标定和重复采样。

性能使用固定数据集记录图像大小、CPU、参数、单节点及整流程耗时、P50/P95、峰值内存；无目标和多目标都测试。不写未经测量的固定 FPS 或“达到商业软件精度”。模型缓存按实际资源摘要和参数失效，输出数量、搜索候选和保留图像均受明确预算限制。

## 8. 开发顺序与完成报告

1. 先读取现状，记录可复现问题和最小规格，选定首批配方及验收数据。
2. 实现多输入和绑定执行，验证一个双来源几何运算可通过完整 C++ → SDK → WPF 链路。
3. 实现坐标与 Fixture，验证 reference/run 位姿、逆变换和旧配方兼容。
4. 扩展 ROI／卡尺、圆／线及双边测量，完成两圆中心距和公差判定。
5. 完成参数、教学、结果表、叠加、保存重载及 SDK 示例，进行受影响回归和独立代码审查。
6. 构建独立本地 Debug 版，记录实际程序路径、构建配置、配套 Runtime 和测试报告。没有执行的测试写明待验证。

可以委派相互独立的源码审查、样本设计或模块任务，但坐标、状态和数据契约只保留一个明确版本，避免不同模块自行发明相似类型。

完成报告简洁说明：新增了哪些可用算子／流程、解决哪些原有冲突、用户怎样配置、运行程序在哪里、实际验证结果，以及尚未实现／尚未实机验证的内容。M3～M6 仍以待办列出，不用“已全面对齐 VisionMaster/VisionPro”概括局部完成。
