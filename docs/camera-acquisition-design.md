# 海康 / 大恒 GigE 相机采集设计

## 2026-10-20 实施状态

当前 C# WPF 源码已实现单台海康 MVS GigE 全局图像源、持续预览与业务触发检测，替代早期“仅本地图像、待实现”的状态。所有 ExternalImage 节点共享一次执行的一张新帧；管理窗按 SN 枚举／连接、开始／停止及读取设备参数，预览视图最多约 5 次／秒刷新，和相机采集帧率独立。ROI／模板使用明确取得的固定教学帧，检测图与结果不被实时预览覆盖。F5 的新帧等待超时为 5 秒，停止／故障／采集代际变化后不会用旧帧完成请求。

实现由 net8 `JPVision.Acquisition` 的 `GlobalCameraService`、`MvsCameraProvider` 和独立可选的原生 MVS 桥接组成。桥接使用已安装官方 SDK，算法 Runtime 不依赖相机 SDK；缺少相机依赖不影响文件图。源模式与首选 SN 单独保存于 `%LocalAppData%\JP-Vision\camera.json`，不保存曝光参数，不随配方保存，也不自动连接。操作、SDK、资源和错误约定见 [全局相机图像源](camera-source.md)。

实机 `ME2P-2622-4GM-P`（SN `GBZ25110055`）已完成两轮各 8 帧 `5120×5120 Gray8` 采集，最终断开，证据见 [实机报告](../artifacts/tests/camera-hardware-capture.json)。MVS 保持连接时首次打开返回 UDP 接收失败 `0x80000214`，释放 MVS 连接后成功；该错误码不统一等于占用。此次短时验证不替代长时间稳定性及拔线恢复验证。

本轮未实现大恒 Galaxy、相机硬件／软件曝光触发、多相机或自动重连；下文保留初期需求和设计背景，超出本节实现范围的能力均为后续方向。

## 初期确认的需求与本机条件（历史背景）

用户选择 GigE 接口、持续预览、触发时检测。采集帧继续进入现有 ExternalImage / Image 输入，复用 ROI、卡尺、模板与检测流程。初期曾考虑 Qt 与 WPF 共用采集契约；当前实现接入 WPF Studio 和现代 .NET WPF 工程，原 Qt 编辑器保留作历史参考。

2026-10-13 本机安装清单含 MVS 5.0.2 和 MVS SDK Development / Runtime 4.8.1.2；开发头文件位于 `C:\Program Files (x86)\MVS\Development\Includes`。当时只检查安装与文档，未连接或控制相机；2026-10-20 的实际接入见上节。未在已检查的安装清单和常用目录找到大恒 Galaxy SDK；大恒适配器需拿到对应 Windows x64 SDK 后开发与实测。具体设备能力在连接后读取。

厂商资料：[海康 MVS / SDK 下载与说明](https://www.hikrobotics.com/en/machinevision/service/download/?module=0)、[大恒 GigE 相机采集模式示例](https://en.daheng-imaging.com/show-105-2499-1.html)。海康本地 SDK 说明了 StartGrabbing → GetImageBuffer → FreeImageBuffer 的取流配对关系，及其与回调取流互斥的限制；实现以对应安装版本的头文件和官方示例为准。

## 预览与检测触发

默认模式为相机连续采集（TriggerMode=Off）。接收线程持续取流，预览只显示最新一帧；用户点击检测、WPF 发起检测或 PLC 发出业务信号时，登记一个检测请求，并使用请求登记之后接收到的新帧执行配方。请求保存触发时间、相机序列号、帧号和实际取帧时间，避免将之前缓存的旧图误作本次检测图。

“触发时检测”在此指算法检测触发，和相机硬件曝光触发是两项独立设置。若后续需要传感器严格同步曝光，需另行实现相机 TriggerMode=On、Line 输入触发模式；该模式通常只在触发时产生新帧，预览保持最近帧，不能承诺同一相机同时保持自由连续取流。当前未提供软件曝光触发、Line0/Line1 或触发沿设置。

检测请求必须给出超时。单工位同一时刻只接受一个检测任务；忙时返回明确 Busy，由 WPF / PLC 决定重试，不无界积压。预览可以覆盖旧帧，已接受的检测帧不能被预览覆盖、重用或静默丢弃。持续每帧检测不是本轮默认需求。

## 采集边界与 WPF 调用

新增独立、可选的 Windows x64 采集模块，厂商适配器统一提供枚举、按序列号打开、参数能力查询、开始/停止、取帧、关闭和错误状态。海康使用 MVS，后续大恒使用 Galaxy；不依靠普通 OpenCV VideoCapture 代替厂商 GigE 驱动。SDK 缺失时本地图像和视觉算法仍能工作，界面明确显示未安装对应 SDK。

公共边界使用 C ABI 的句柄、固定大小结构体和显式帧释放；C++ 与 C# / WPF 不交换厂商结构、cv::Mat、Qt 对象或分配器所有权。C# 采集封装通过 SafeHandle 和异步操作管理资源，输出统一的 Gray8 / Bgr24 帧，直接送入现有 VisionFrame / VisionSession。这样同一视觉配方可由文件图或相机图执行，无需把相机 SDK 调用嵌入每个算法模块。

采集连接配置与检测配方分开保存。当前海康连接按序列号选设备，IP 只作诊断信息；已支持停流后按设备能力设置曝光、增益和帧率，未提供网卡、像素格式或触发模式设置。当前保存源模式与首选 SN，不持久化采集参数；运行关联帧元数据。后续若需完整采集设置审计，应单独扩展运行记录。MVS 与 JP-Vision 不应同时独占打开同一设备，用户应先释放其他客户端连接。

## 内存、线程与 GigE 约束

厂商图像缓冲在释放前必须复制或转换到 JP-Vision 自己拥有的缓冲区，所有失败/取消路径均释放 SDK 帧。Bayer、RGB、Mono10/12/16 等格式按厂商转换 API 和明确规则转换；禁止把未知格式直接当作 Bgr24。帧大小沿用现有 32MP / 128MiB 输入上限。

采集线程只负责取帧与转换；GUI 预览在 GUI 线程刷新，检测在现有后台会话执行。预览缓存容量为 1，当前管理窗每 200 ms 刷新，显示接收 FPS、帧数和预览替换数；替换数不等于网络丢包数。不为每个预览帧保留算法中间图。断线停止接受检测，等待中的请求按异常/超时收尾；恢复需手动断开并按原 SN 连接，不自动重连或换机。启动、停止、断开与退出应用等待采集资源收尾；关闭管理窗本身只关闭视图。

GigE 使用 SDK 查询适宜包大小和实际带宽，不能假定所有网卡支持相同巨帧。5120×5120 的 Mono8/Bayer8 单帧约 25MiB，1Gbps 链路仅按像素载荷计算的上限约 4.77 帧/秒，实际还要扣除协议及链路开销；不承诺这种分辨率下可达 30FPS。帧率、相机图像 ROI、像素格式和网络带宽需一起确定。

## 实施与后续验收

1. 已实现公共采集句柄、拥有像素的帧契约和可选 SDK 动态加载；采集服务保持机器绑定许可证检查。
2. 已实现海康 GigE 枚举、参数查询、连续取流、像素转换、停止与故障状态，并完成上述单机短时实测。
3. 已接入 WPF 相机管理、全局图像源、固定教学图及业务触发检测，区分实时预览和本次检测图；未接入历史 Qt 编辑器。
4. 后续补充长时间内存趋势、拔线恢复、其他机型／像素格式及生产环境验收；自动重连与曝光触发需单独设计实现。
5. 安装对应大恒 SDK 后补齐 Galaxy 适配器，沿用同一帧契约并独立实测；多相机仍为后续范围。

完整验收目标仍包含：连续预览不自动逐帧运行配方；检测结果关联实际帧；旧帧不能冒充新触发帧；错误时不能产生合格结果；反复开始/停止和拔线恢复无缓冲泄漏；退出时无采集线程残留；未授权电脑不能运行受保护功能。文件图、模拟采集验证及本次短时取流不能替代尚未完成的长期／故障场景实机验收。
